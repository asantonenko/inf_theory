### Крок 1. Класична («повна») форма мінімальної програми

Мова C# — об'єктноорієнтована, і в її «класичному» вигляді **будь-який код має бути всередині типу** (класу, структури, запису). Тому мінімальна програма C# у класичній формі виглядає так:

```csharp
class Program
{
    static void Main()
    {
    }
}
```

Розберемо цей запис.

- `class Program` — оголошення класу з ім'ям `Program`. Ім'я `Program` — це лише традиція (так називає клас шаблон Visual Studio), компілятору підійшло б будь-яке коректне ім'я, наприклад `class MyApp`.
- `Main` — це **точка входу** програми (англ. *entry point*), повний аналог функції `main` у C/C++. Виконання програми полягає у виконанні методу `Main`: воно починається з першого оператора `Main` і завершується виходом із нього.
- **Увага:** на відміну від C/C++, де точка входу пишеться з малої літери (`main`), у C# метод називається саме `Main` — з великої `M`. C# чутливий до регістру, і `main` точкою входу **не** буде (компілятор видасть помилку CS5001 «Program does not contain a static 'Main' method suitable for an entry point»).
- `static` — метод належить класу, а не окремому об'єкту; це обов'язково для точки входу (адже до старту програми ще немає жодного об'єкта, який можна було б створити).
- `void` — метод не повертає жодного значення (у C/C++ ми домовилися завжди писати `int main()`, у C# ж `void Main()` — цілком легальний і поширений варіант).
- У фігурних дужках — тіло методу, тобто набір операторів. Тут їх немає жодного: програма запускається і одразу завершується.

Компілятор C# допускає для точки входу лише такі підписи (будь-який з них — на ваш вибір):

```csharp
static void Main()                  // без параметрів, без результату
static void Main(string[] args)     // з параметрами командного рядка
static int  Main()                  // повертає код завершення
static int  Main(string[] args)     // і те, й інше
// а також асинхронні варіанти:
static async Task Main()  /  static async Task<int> Main(string[] args)   // і т.д.
```

**Код завершення програми.** Як і в C/C++, програма повертає операційній системі ціле число: за угодою `0` — успішне завершення, будь-яке інше значення — що сталася помилка. Якщо `Main` оголошений як `void`, операційній системі автоматично повертається `0`. Якщо ж ми хочемо повернути щось інше:

```csharp
class Program
{
    static int Main()
    {
        return 2 + 2;   // програма поверне ОС число 4
    }
}
```

Зверніть увагу: на відміну від C, у C# **не можна «просто не написати» `return`**, якщо метод оголошений як `int Main()` — компілятор видасть помилку. Або `void` без `return`, або `int` з обов'язковим `return`. Ще один спосіб задати код завершення — властивість `Environment.ExitCode` або метод `Environment.Exit(код)`, але ним ми користуватимемося рідко.

**Ще одна відмінність від C/C++.** Програма C# — це не окремий самодостатній файл, а **проєкт**: крім файлу з кодом (традиційно `Program.cs`) існує файл проєкту (`*.csproj`), у якому вказано, для якої версії платформи .NET ми збираємо програму:

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net9.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
  </PropertyGroup>
</Project>
```

Такий проєкт створюється однією командою `dotnet new console`, а запускається командою `dotnet run`. В онлайн-IDE усе це робиться за вас — ви пишете тільки вміст `Program.cs`. Компілятор C# перетворює код не в машинний код процесора, а в **проміжну мову IL**, яку вже під час запуску виконує (компілює «на льоту») середовище виконання .NET — саме тому одна й та сама скомпільована програма працює під Windows, Linux і macOS.

### Крок 2. Скорочена (сучасна) форма: top-level statements

Починаючи з **C# 9** (2020 р., .NET 5) з'явилася можливість писати операторів **прямо в корені файлу**, без класу і без методу `Main`. Ця можливість називається *top-level statements* («операторами верхнього рівня»), і саме її використовує сучасний шаблон `dotnet new console`. Тоді мінімальна програма стає одним рядком:

```csharp
return 0;
```

або, наприклад, такою (програма, яка нічого не робить, але щось таки містить):

```csharp
System.Console.Write("");
```

**Важливий нюанс:** *повністю порожній* файл програмою не є — на відміну від C++, де `int main(){}` є коректною мінімальною програмою, у C# у проєкті мусить бути точка входу, і якщо у файлі немає ні `Main`, ні жодного оператора верхнього рівня, отримаємо помилку компіляції CS5001. Тобто «найкоротша» коректна програма C# — це один оператор, наприклад `return 0;`.

Насправді ніякої магії тут немає: компілятор сам «загортає» ваші оператори у клас із методом-точкою входу. Залежно від того, що є у вашому коді, генерується один із підписів:

| Що містить код верхнього рівня | Який `Main` генерує компілятор |
|---|---|
| ні `await`, ні `return` | `static void Main(string[] args)` |
| `return` (зі значенням) | `static int Main(string[] args)` |
| `await` | `static async Task Main(string[] args)` |
| `await` і `return` | `static async Task<int> Main(string[] args)` |

Тому й у скороченій формі працює `return 0;` (код завершення) і доступна змінна `args` — масив аргументів командного рядка, який ви ніде не оголошували.

**Правила, які треба знати:**

1. Файл з операторами верхнього рівня в проєкті може бути **тільки один** (інакше — помилка: дві точки входу). Решта файлів — звичайні, з класами.
2. Оператори верхнього рівня мають стояти **на початку файлу**: після них можна оголошувати простори імен, класи, методи — але не перед ними.
3. Директиви `using` — теж перед операторами верхнього рівня.
4. Обидва стилі компілюються практично в **однаковий IL-код**, тобто швидкодія однакова, різниця чисто синтаксична.

### Крок 3. Порівняння двох форм і що вибрати

```csharp
// КЛАСИЧНА ФОРМА                        |  // СКОРОЧЕНА ФОРМА
using System;                            |  Console.WriteLine("Привіт!");
                                         |
namespace HelloApp                       |
{                                        |
    class Program                        |
    {                                    |
        static void Main(string[] args)  |
        {                                |
            Console.WriteLine("Привіт!");|
        }                                |
    }                                    |
}                                        |
```

| | Класична форма (`class` + `Main`) | Скорочена форма (top-level statements) |
|---|---|---|
| З якої версії | з C# 1.0 (2002) | з C# 9.0 (.NET 5, 2020) |
| Видно точку входу | так, явно | ні, її генерує компілятор |
| Кількість «церемоній» | 4 конструкції до першого корисного рядка | 0 |
| `args`, `return`, `await` | пишемо самі в підписі | доступні автоматично |
| Скільки таких файлів у проєкті | скільки завгодно класів, але один `Main` | лише один файл |
| Де зручніша | великі проєкти, навчання ООП, старі компілятори (Mono, .NET Framework), співбесіди | навчальні задачі, скрипти, утиліти, олімпіадні задачі |
| Швидкодія | однакова | однакова |

**Практична порада для цього курсу.** Скорочена форма коротша і чудова для навчальних задач, але:
- вона **не компілюється** старими компіляторами — .NET Framework, Mono, старі версії онлайн-компіляторів (а саме Mono часто стоїть у деяких перевіряльних системах);
- майбутній роботодавець і будь-який реальний проєкт усе одно покаже вам класичну форму.

Тому: **вміти треба обидві**, а надсилати в систему перевірки надійніше класичну (вона компілюється будь-де). Далі в курсі я показуватиму приклади у скороченій формі (щоб не відволікатися на «обгортку»), а поруч, де це важливо, наводитиму повний варіант.

Ще дві сучасні «скорочувальні» дрібниці, які варто знати одразу:

- **Implicit usings** (C# 10 / .NET 6): у новому проєкті ввімкнено `<ImplicitUsings>enable</ImplicitUsings>`, і тоді `using System;` (а також `System.Linq`, `System.Collections.Generic` тощо) додаються автоматично — саме тому в однорядковій програмі можна писати просто `Console.WriteLine`. Якщо ця опція вимкнена (або ви працюєте на старому компіляторі), `using System;` треба написати самому, або звертатися повним іменем: `System.Console.WriteLine(...)`.
- **File-scoped namespace** (C# 10): замість вкладеного блоку можна писати `namespace HelloApp;` одним рядком на початку файлу, і не робити зайвий рівень відступу.

## 1.3 Програма "Привіт, світе!"

### Крок 1. «Привіт, світе!» у класичній формі

За традицією (започаткованою книгою Керніґана і Річі «Мова програмування Сі») почнемо з програми, яка виводить рядок `Привіт, світе!`. Класичний, «повний» вигляд програми C#:

```csharp
// Програма Привіт, світе!
using System;

namespace HelloWorld
{
    class Program
    {
        static void Main(string[] args)
        {
            Console.WriteLine("Привіт, світе!");
        }
    }
}
```

- Перший рядок — **коментар**. Коментар у C# ідентичний коментарю C++: усе від `//` до кінця рядка компілятор ігнорує. Так само працюють багаторядкові коментарі `/* ... */`. Є ще третій вид — документаційний коментар `///` (з нього генерується довідка та підказки IntelliSense), про нього поговоримо пізніше.
- `using System;` — це **не** аналог `#include <iostream>`! У C# немає препроцесора і немає заголовних файлів: класи беруться зі скомпільованих збірок (assembly). Директива `using System;` лише дозволяє **не писати повне ім'я** класу, тобто це найближчий аналог рядка `using namespace std;` з C++. Без цієї директиви програма теж працюватиме, але писати доведеться так:

  ```csharp
  System.Console.WriteLine("Привіт, світе!");
  ```

  Порівняйте: `std::cout` у C++ ↔ `System.Console` у C#.
- `Console` — клас із простору імен `System`, який відповідає за роботу з консоллю (те саме «чорне вікно»). `Console.Out` — це **стандартний потік виведення**, аналог `std::cout` і `stdout`.
- `Console.WriteLine("...")` — виводить рядок і **переводить курсор на наступний рядок**. Тобто `WriteLine` = виведення + перехід на новий рядок; це аналог `printf("...\n")` або `cout << ... << endl`.
- Рядкова константа, як і в C/C++, — у подвійних лапках, і символ `\` («зворотний слеш») у ній має особливе значення: `\n` — перехід на новий рядок, `\t` — табуляція, `\"` — сама подвійна лапка, `\\` — один зворотний слеш.
- Наприкінці кожного оператора — крапка з комою; після закриваючої фігурної дужки блоку крапка з комою не ставиться.

Якщо ми не хочемо переводити курсор на новий рядок, використовуємо `Console.Write`:

```csharp
Console.Write("Привіт, світе!");        // без переходу на новий рядок
Console.Write("Привіт, світе!\n");      // те саме, що Console.WriteLine("Привіт, світе!")
```

Тобто відповідність така:

| C | C++ | C# |
|---|---|---|
| `printf("Текст\n");` | `cout << "Текст" << endl;` | `Console.WriteLine("Текст");` |
| `printf("Текст");` | `cout << "Текст";` | `Console.Write("Текст");` |
| `printf("\n");` | `cout << endl;` | `Console.WriteLine();` |

**Примітка про `endl`.** У C++ `endl` — це не лише перехід на новий рядок, а й виштовхування буфера потоку. У C# аналогом виштовхування є `Console.Out.Flush()`, але викликати його майже ніколи не потрібно: стандартний потік виведення консолі за замовчуванням має `AutoFlush = true`. Тобто `Console.WriteLine` уже поводиться «як `endl`».

**Примітка про `\n` і `Environment.NewLine`.** `WriteLine` дописує в кінець не обов'язково `\n`, а системний розділювач рядків: під Linux/macOS це `"\n"`, під Windows — `"\r\n"`. У більшості перевіряльних систем це нічого не змінює, бо `\r` при порівнянні відкидається; але якщо колись треба гарантовано вивести саме `\n`, пишіть `Console.Write("Текст\n")`.

**Примітка про українські літери.** Файли C# за замовчуванням у кодуванні UTF-8, і в Linux/онлайн-IDE українські літери виводяться без проблем. Якщо ж ви запускаєте програму в консолі Windows і бачите «кракозябри» замість українських букв, додайте на початку `Main` рядок

```csharp
Console.OutputEncoding = System.Text.Encoding.UTF8;
```

(або виконайте `chcp 65001` у консолі), або, за прикладом розділу про C, привітайте світ рядком `"Hello, world!"`.

### Крок 2. «Привіт, світе!» у скороченій формі

А тепер та сама програма у сучасному стилі — з операторами верхнього рівня та неявними `using`:

```csharp
// Програма Привіт, світе!
Console.WriteLine("Привіт, світе!");
```

Це **повна** програма: саме такий (з точністю до коментаря) вміст файлу `Program.cs` створює команда `dotnet new console` у .NET 6 і новіших. Один рядок замість дев'яти — при абсолютно однаковому результаті й однаковому скомпільованому IL-коді.

Проміжні варіанти, які теж корисно розпізнавати:

```csharp
// 1) top-level statements, але з явним using (працює і без implicit usings)
using System;

Console.WriteLine("Привіт, світе!");
```

```csharp
// 2) класична форма, але з file-scoped namespace (C# 10) і без параметрів Main
namespace HelloWorld;

class Program
{
    static void Main() => Console.WriteLine("Привіт, світе!");
}
```

У другому прикладі використано **лямбда-стрілку `=>`** для методу з одного оператора (*expression-bodied member*) — ще один спосіб скорочення запису, який ви часто побачите в чужому коді.

**Різниця, яку треба чітко розуміти:** скорочена форма — це синтаксичний цукор. Клас і метод-точка входу існують, просто їх написав за вас компілятор (він генерує клас `Program` з методом зі спеціальним іменем `<Main>$`). Тому в скороченій формі ви **не можете**: мати два такі файли в проєкті; поставити оператори після оголошення класів; вибрати точку входу опцією компілятора `-main`. А ще: у скороченій формі нікуди не подінеться потреба оголошувати власні класи — просто їх пишуть **нижче** операторів верхнього рівня.

### Крок 3. Виведення кількох рядків

Щоб вивести два рядки, можна двічі викликати `Console.WriteLine`:

```csharp
Console.WriteLine("Це перший рядок!");
Console.WriteLine("А це другий рядок!");
```

або один раз, вставивши `\n` у середину рядкової константи:

```csharp
Console.WriteLine("Це перший рядок!\nА це другий рядок!");
```

Результат в обох випадках однаковий:

```
Це перший рядок!
А це другий рядок!
```

Якщо в першому виклику замінити `WriteLine` на `Write` (тобто «забути» перехід на новий рядок), рядки склеяться:

```csharp
Console.Write("Це перший рядок!");
Console.WriteLine("А це другий рядок!");
```

```
Це перший рядок!А це другий рядок!
```

А якщо не перевести рядок після **останнього** рядка виведення, візуально нічого не зміниться — просто наступне виведення (уже інших програм) може злитися з вашим останнім рядком. Тому й прийнято завершувати виведення переходом на новий рядок.

**Аналог «одного оператора з багатьма `<<`».** У C++ можна вивести все одним оператором, багаторазово застосувавши `<<`. У C# найближчі за духом засоби такі:

```csharp
// а) конкатенація рядків операцією +
Console.WriteLine("Це перший рядок!\n" +
                  "А це другий рядок!");

// б) інтерполяція рядків (знак $ перед лапками) — знадобиться далі в курсі
int a = 2, b = 2;
Console.WriteLine($"{a} + {b} = {a + b}");        // виведе: 2 + 2 = 4

// в) дослівний (verbatim) рядок @"..." — переноси рядків беруться прямо з коду,
//    а \ не має особливого значення
Console.Write(@"Це перший рядок!
А це другий рядок!
");

// г) «сирий» рядковий літерал (raw string literal), C# 11 і новіші
Console.Write("""
    Це перший рядок!
    А це другий рядок!
    """);
```

Варіанти (в) і (г) особливо зручні, коли треба вивести «картинку» з багатьох рядків: не потрібно ні `\n`, ні екранування лапок і зворотних слешів. Але пам'ятайте: `"""..."""` вимагає компілятора C# 11+, тому в старих онлайн-компіляторах і на Mono він не спрацює.

### Крок 4. Де писати й запускати програми C#: IDE

Щоб перевірити, як працює програма, потрібне **інтегроване середовище розробки** (IDE). Для C# є як офлайнові, так і онлайнові варіанти.

**Офлайнові (встановлюються на комп'ютер):**
- **Visual Studio Community** — безкоштовна для навчання й індивідуальної розробки, Windows (і macOS-версія раніше), «еталонна» IDE для C#;
- **Visual Studio Code** + розширення **C# Dev Kit** — кросплатформово (Windows/Linux/macOS), безкоштовно;
- **JetBrains Rider** — потужна кросплатформова IDE, безкоштовна для некомерційного використання;
- зовсім мінімальний варіант: **.NET SDK** + будь-який текстовий редактор і команди `dotnet new console`, `dotnet run`.

**Онлайнові (потрібен лише браузер):**
- **.NET Fiddle** (`dotnetfiddle.net`) — найзручніший саме для C#: свіжі версії C#, шаблони (Console/Script), кнопка **Run**, збереження й `Share` посиланням, підтримка NuGet-пакетів;
- **OnlineGDB** (`onlinegdb.com/online_csharp_compiler`) — той самий сервіс, яким ви користувалися для C/C++, лише виберіть у списку мову C#; є справжній відлагоджувач (debugger), кнопки **Run**, **Fork this**, **Share**;
- **myCompiler**, **Programiz**, **Replit**, **ideone** (у списку мов є C#) — теж придатні; зверніть увагу, що частина цих сервісів працює на **Mono** і на старому наборі можливостей мови, тому там **top-level statements можуть не компілюватися** — використовуйте класичну форму з `class Program` і `Main`;
- **SharpLab** (`sharplab.io`) — не зовсім IDE, але надзвичайно корисна річ: показує, у що саме компілятор перетворює ваш код (у тому числі як «розгортається» скорочена форма в клас із `Main`).

**Завдання кроку:** запустіть програму «Привіт, світе!» послідовно на .NET Fiddle і на OnlineGDB — спершу в класичній формі, потім у скороченій, і перевірте, де скорочена форма компілюється, а де ні. Щоб змінити чужу програму, натисніть `Fork`/`Fork this` (або просто відредагуйте код) і знову `Run`.

**Підказка:** якщо ви налаштовані серйозно користуватися .NET Fiddle або OnlineGDB — зареєструйтеся (в OnlineGDB можна зайти через Google/Facebook/GitHub). Тоді ваші програми зберігатимуться в акаунті, і доступ до них буде з будь-якого місця, де є Інтернет. 

### Крок 6. Задача: «ПРИВІТ!»

Напишіть програму, яка виведе напис:

```
ППППП  РРРРР  И   И  ВВВВВ   І  ТТТТТ  !!
П   П  Р   Р  И  ИИ  В   В   І    Т    !!
П   П  РРРРР  И И И  ВВВВ    І    Т    !!
П   П  Р      ИИ  И  В   В   І    Т    
П   П  Р      И   И  ВВВВВ   І    Т    !!
```

**Підказка.** Використайте кілька викликів `Console.WriteLine` (по одному на кожен рядок «картинки») — або один виклик `Console.Write` із символами `\n` між рядками, — або дослівний рядок `@"..."`, у який можна вставити всю картинку цілком:

```csharp
Console.Write(@"ППППП  РРРРР  ...
П   П  Р   Р  ...
");
```

Можете скористатися copy-paste наведеного вище тексту, щоб не помилитися в набиранні рядків (враховуйте кількість пробілів для поділу літер; пробіли в кінці рядків можуть бути або не бути — це не впливає на правильність рішення).

Зверніть увагу: якщо ви пишете картинку через `@"..."`, то **відступ на початку рядків не додається автоматично** — усе, що стоїть у коді після лапок, виводиться дослівно, тому не робіть зайвих відступів для «красоти». А в raw string literal (`"""..."""`, C# 11+) навпаки: спільний відступ закриваючих лапок автоматично відкидається — це зручно, але доступно лише на нових компіляторах.

# Зауваження до наявних матеріалів C/C++

Позначу окремо мовно-редакційні й окремо технічні моменти.

## Редакційні / мовні

1. **1_3_2 наполовину російською.** Друга половина сторінки не перекладена: «Необходимо заметить, что хотя данная строка… и удобна для новичков…», «Если Вы хотите напечатать две строки…», і приклади виводять `"Это первая строка!"`, `"А это вторая строка!"`. Це варто перекласти («Це перший рядок!», «А це другий рядок!»), інакше вихід прикладів не збігається з рештою курсу.
2. **Русизми-«хвостики» у тексті:** у 1_3_2 — «конструкції `std::cout` **и** `std::endl`», «на OnlineGDB, cpp.sh **или** ideone»; у 1_3_4 — «Майже ту ж програму». Краще: «та», «або», «Майже ту саму програму».
3. **1_3_2, приклад із `\n`:** написано `std::cout << "Привіт, мир!\n";` — тут «мир» замість «світе», тобто рядок не збігається з програмою, про яку йде мова. Має бути `"Привіт, світе!\n"`.
4. **1_3_1:** слово «краказябри» — просторічне й до того ж із помилкою; краще «кракозябри (нечитабельні символи)» або нейтрально «замість українських літер ви можете побачити нечитабельні символи».
5. **1_3_1, фраза «Будь-який текст у подвійних лапках позначатиме рядкову константу, а якщо ми хочемо використовувати подвійну лапку в рядковій константі, то перед нею потрібно поставити знак “зворотний сліш”»** — тут два різні твердження злиті в одне речення, читач може подумати, що зворотний слеш стосується всієї константи. Варто розбити на два речення. І уніфікувати термін: у тексті зустрічаються «зворотний сліш» і «сліш» — усталене українське написання «слеш» / «обернена коса риска».
6. **1_2_1** містить один абзац російського залишку граматики («Зауважимо, що, функція `main` не повинна повертати нуль») — тут ще й змістова двозначність: читається як «не має права повертати нуль», а мається на увазі «не зобов'язана повертати нуль». Раджу переформулювати: «Функція `main` не зобов'язана повертати саме нуль».
7. **1_3_5:** у зразку виводу в 4-му рядку відсутні `!!` (це, очевидно, задумано — «розрив» перед точкою знака оклику), але учні часто сприймають це як помилку умови. Варто додати рядок: «зверніть увагу: у четвертому рядку знаків оклику немає — так і треба».

## Технічні / змістові

8. **`int main()` vs `int main(void)` у C.** У розділі 1_2_1 сказано, що «в круглих дужках вказані параметри — в даному випадку параметрів немає». У **C++** це справді так, а от у **C** порожні дужки історично означають «інформація про параметри відсутня» (стара форма K&R), а не «параметрів немає». Правильна форма для C — `int main(void)`. (У C23 `()` остаточно прирівняли до `(void)`, але для сумісності зі старішими компіляторами зауваження варте одного речення.) Оскільки курс декларує сумісність прикладів із компілятором C++, можна залишити `int main()`, але про цю різницю варто згадати.
9. **Про неявний `return 0`.** Формулювання «в сучасних версіях C (починаючи з C99) і C++ (починаючи з C++11) у функції `main` можна не писати `return`» — щодо C++ це справедливо ще з **C++98**: стандарт від початку дозволяє випадання з кінця `main` з результатом 0. Обмеження «починаючи з C++11» тут зайве (з C++11 пов'язані інші зміни). Для C дата C99 правильна.
10. **Про діапазон коду завершення.** Приклад `return 2+2;` бездоганний, але варто попередити: в POSIX-системах (Linux/macOS) батьківському процесу передаються лише **молодші 8 бітів**, тобто `return 256;` перетвориться на 0, а `return -1;` побачиться як 255. Також доречно згадати `EXIT_SUCCESS` / `EXIT_FAILURE` з `<stdlib.h>`.
11. **`\n` — один символ, але не завжди один байт на виході.** У 1_3_1 правильно сказано, що `\n` — один символ. Варто додати: у Windows при виведенні в текстовому режимі він перетворюється у два байти `CR LF`. Це часто спантеличує, коли учень порівнює розмір файлу або вивід із очікуваним.
12. **Українські літери в консолі Windows.** Порада «привітати світ рядком `"Hello, world!"`» — робоча, але надто капітулянтська. Варто поруч дати справжнє рішення: `chcp 65001` у консолі, або (в MSVC) `SetConsoleOutputCP(CP_UTF8)`, або збереження файлу в UTF-8 з BOM + прапорець `/utf-8` для MSVC. У Code::Blocks/MinGW достатньо `chcp 65001` і шрифту з підтримкою кирилиці.
13. **`endl` vs `'\n'` у C++.** У 1_3_2 добре пояснено, що `endl` додатково виштовхує буфер. Варто одразу додати практичне зауваження, бо воно економить студентам години на олімпіадних задачах: у циклах із великим обсягом виведення `endl` суттєво **сповільнює** програму, і краще писати `'\n'`, а `endl` (або `std::flush`) використовувати лише там, де виштовхування реально потрібне.
14. **Про `using namespace std;`.** Текст справедливо застерігає, що це погана практика. Можна підсилити конкретикою причини (колізії імен: `std::count`, `std::size`, `std::data`, `std::byte` проти власних змінних) — одне речення дуже допомагає, бо інакше застереження звучить як «просто так домовились».
15. **1_3_4, набір онлайн-IDE.** `cpp.sh` (C++ Shell) уже давно тримає **застарілий компілятор** (і періодично недоступний) — варто або попередити про це, або замінити його. Дуже раджу додати до списку **Compiler Explorer (godbolt.org)**: він дозволяє вибрати десятки версій компіляторів і побачити асемблер — надзвичайно корисно навіть на початковому рівні (наприклад, наочно показати, що `int main(){}` і `int main(){return 0;}` дають однаковий код). Також варто додати **Programiz** / **Replit** як зрозумілу заміну ideone, інтерфейс якого й самі автори називають «трохи заплутаним».
16. **1_3_4: «прямі посилання на цю програму»** — у тексті слова «OnlineGDB», «cpp.sh», «ideone», «Wandbox» подані як посилання, але в наданому HTML самі URL відсутні. Якщо це втрата при експорті — треба перевірити, бо крок без посилань не виконується. І окремо: онлайн-«шпаргалки» такого типу мають властивість вмирати — варто дублювати завдання інструкцією «відкрийте сервіс і вставте код», щоб крок не залежав від живучості посилань.
17. **1_3_1: «мінімальна за довжиною програма».** У 1_2_1 сказано, що `int main(){}` — мінімальна програма, «яка працюватиме у будь-якій версії мов C та C++». Строго кажучи, у C89 випадання з кінця `int main` дає невизначене значення коду завершення, тож «у будь-якій версії» точніше стосується варіанта `int main(){return 0;}`, який і подано першим — просто варто чіткіше зв'язати ці два твердження.
18. **`iostream` без `.h`.** Пояснення правильне; можна додати, що для C-функцій у C++ правильні імена — `<cstdio>`, `<cstdlib>` (а не `<stdio.h>`), хоча старі форми теж працюють. Це логічно згадати саме тут, бо далі в курсі `printf` і `cout` вживаються поруч.
19. **Змішування `printf` і `cout`.** У задачі 1_3_5 підказка пропонує на вибір `printf` або `cout` — це добре, але варто одноразово попередити: **не варто змішувати** їх в одній програмі без потреби (через окремі буфери може «переплутатися» порядок виведення; лікується `std::ios_base::sync_with_stdio(true)`, який увімкнено за замовчуванням, але учням корисно про це почути).
20. **Дрібниця щодо 1_3.html / 1_2.html:** сторінки-«обкладинки» містять лише перелік «Крок 1…Крок 5» без назв кроків. Якщо це навігація, варто додати назви (наприклад «Крок 1. Hello world мовою C», «Крок 2. Hello world мовою C++», «Крок 3. Знайомство зі stepik», «Крок 4. Онлайн IDE», «Крок 5. Задача “ПРИВІТ!”») — це помітно полегшує повернення до потрібного матеріалу.
